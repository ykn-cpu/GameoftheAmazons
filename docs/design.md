## 核心数据结构

```
棋盘：int gridInfo[8][8]
  0  = 空格
  1  = 黑棋 (grid_black)
  -1 = 白棋 (grid_white)
  2  = 障碍 (obstacle)
```

方向数组：8 个方向（上下左右 + 四对角线）。

注：棋盘坐标系与 Botzone 官方不同，横纵坐标恰好颠倒，需在 Botzone 版中 swap 转换。

---

## 走法合法性判定 `legal()`

1. 起点必须是当前行动方棋子
2. 目标格必须为空
3. 起点 → 目标格：直线（横/竖/斜），路径上无阻挡
4. 目标格 → 射箭位置：同上
5. 允许射箭回到起点位置，但不允许射箭落在目标格
6. 胜负判定时机：每方落子前检查是否仍有合法走法

## AI 算法

### 搜索框架

- **Minimax**：我方层（MAX）最大化评估值，对方层（MIN）最小化
- **Alpha-Beta 剪枝**：维护 α（下界）和 β（上界），α ≥ β 时剪枝
- **迭代加深**：深度从 1 逐步加深到 5，在 950ms 时限内
- **走法排序**：搜索前用快速评估函数预排序，优先搜索高价值分支
- **步长压缩**：走子和射箭步长限制为 4，减少分支因子
- **兜底逻辑**：超时时返回当前深度最优解，防止 AI 在有合法走法时提前认输

### 评估函数

#### 走法排序用（快速评估）

```
score = fastMobility_diff × 1 + blockScore × 3 + territory_score × 35
```

#### Minimax 叶子节点用（精确评估）

```
score = fastMobility_diff × 1 + blockScore × 2 + territory_score × 7
```

两套权值的原因：排序时更看重领地优势（35×）以引导搜索方向；叶子节点评估降低领地权重（7×）避免过度保守。

#### 三个子函数

| 函数 | 计算方式 | 作用 |
|------|----------|------|
| `fastMobility` | 每棋子 × 8 方向 × 可达步数（限 4 步）× 5 | 保持活动空间 |
| `blockScore` | 障碍邻格有对方棋子则 +10 | 攻击性：限制对手 |
| `territory_score` | BFS 计算双方可达区域，取差值 | 领地控制，权重最高 |

### 参数调优方法

1. 先确定领地评估权重应为三者最大（20~50），前两者较小（1~10）
2. 让 AI 与基线对手对弈（mobility 贪心、动态贪心、混合贪心、MCTS）
3. AI 过于保守 → 提高 `blockScore` 和 `fastMobility` 权重
4. AI 过于激进 → 提高 `territory_score` 权重
5. 超时 → 减小搜索深度或缩短思考时限

## 图形界面设计

### 视觉层次

背景 → 棋盘外框 → 棋盘格子 → 高亮覆盖层 → 棋子/障碍 → 状态栏 → 文字提示，逐层绘制保证正确的遮挡关系。

### 阴影与高光

- **棋盘格子**：每格绘制 8 层右下偏移灰色渐变阴影，格子本身白色填充覆盖在上
- **棋子**：同心圆阴影渐变（外深内浅），棋子本体再加边框描边
- **合法路径**：黄色（移动）/ 红色（射箭）高亮，同样叠加 8 层阴影渐变
- **鼠标悬停**：可交互棋子显示绿色光晕，按钮显示黄色高亮

### 交互流程

1. **选子**：鼠标移至合法己方棋子时绿色光晕高亮 → 点击选中。此阶段允许悔棋（重新点击另一棋子）
2. **选目标**：合法移动路径以黄色渐变高亮显示 → 点击空格确认
3. **选射箭**：合法射箭位置以红色渐变高亮显示 → 点击确认，走法生效

每步有状态栏文字提示（"请点击棋子"→"请选择目标位置"→"请选择射箭位置"），AI 走完后提示栏显示上一步走法坐标。

### 按钮与提示

- 圆角矩形按钮 + Unicode 图标 + 醒目配色
- 选子阶段：存盘按钮可用；走棋中途：存盘按钮隐藏（防止误触破坏状态）
- 菜单选择、执方选择配有提示音（PlaySound）+ MessageBox 弹窗

## Botzone 平台适配

- 坐标顺序为 `(y, x)` 而非 `(x, y)`，输入输出均需 swap 转换
- 第一回合收到 `-1` 表示执黑，否则执白
- 从 `turnID` 逐步还原历史棋局，模拟所有已进行的走法
